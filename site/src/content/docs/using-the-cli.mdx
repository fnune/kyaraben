You can configure all of Kyaraben with its config file and control it from the command line.

## The config file

Kyaraben stores its configuration in `~/.config/kyaraben/config.toml`. The UI writes its changes to this file, and shows the changes that you make in the file.

You do not need to edit the file. Edit it if you prefer a text editor or want to keep your setup in version control.

### Example

```toml
[global]
collection = "~/Emulation"

[systems]
snes = ["retroarch:bsnes"]
psx = ["duckstation"]
gamecube = ["dolphin"]
ps2 = ["pcsx2"]

[emulators.duckstation]
version = "v0.1-10655"

[frontends.esde]
enabled = true

[sync]
enabled = true
```

### `[global]`

| Key          | Type   | Default       | Description                                          |
| ------------ | ------ | ------------- | ---------------------------------------------------- |
| `collection` | string | `~/Emulation` | Path to the collection                               |
| `headless`   | bool   | `false`       | Sync-only mode: creates directories, skips emulators |

### `[graphics]`

| Key       | Type   | Default  | Description                                                    |
| --------- | ------ | -------- | -------------------------------------------------------------- |
| `shaders` | string | `manual` | Global shader setting: `recommended`, `on`, `off`, or `manual` |

`recommended` enables shaders only for the emulators where they work well. Overrides in `[emulators.<id>]` take precedence.

### `[savestate]`

| Key      | Type   | Default    | Description                                                       |
| -------- | ------ | ---------- | ----------------------------------------------------------------- |
| `resume` | string | `autosave` | Global resume setting: `autosave`, `autoload`, `off`, or `manual` |

`autosave` writes a savestate when you quit. `autoload` also loads that savestate on the next launch. Both apply only to emulators with reliable resume support. Overrides in `[emulators.<id>]` take precedence.

The older value `recommended` now means `autosave`. Autoload is opt-in, because a load of the last savestate on each launch can overwrite progress that you want to keep.

### `[systems]`

Maps each system ID to a list of one or more emulator IDs.

```toml
[systems]
snes = ["retroarch:bsnes"]
psx = ["duckstation"]
```

### `[emulators.<id>]`

Optional per-emulator configuration:

```toml
[emulators.duckstation]
version = "v0.1-10655"
shaders = "on"
resume = "autosave"
```

- `version`: pins a specific version. The default is the latest supported version.
- `shaders`: enables managed CRT/LCD shaders. Values: `on`, `off`, `manual`. The default is the global `[graphics]` setting.
- `resume`: sets auto-resume. Values: `autosave`, `autoload`, `off`, `manual`. The default is the global `[savestate]` setting. The older value `on` means `autosave`.

### `[frontends.<id>]`

Frontend configuration:

```toml
[frontends.esde]
enabled = true
```

### `[sync]`

Synchronization configuration.

```toml
[sync]
enabled = true
autostart = true

[sync.syncthing]
listen_port = 22100
discovery_port = 21127
gui_port = 8484
relay_enabled = true

[sync.ignore]
patterns = [
  "**/shader_cache/**",
  "**/logs/**",
]
```

With `autostart`, Syncthing starts when you log in. On Steam Deck, this works in Desktop Mode and in Game Mode.

See [`kyaraben sync`](#kyaraben-sync) for available commands.

## Commands

### `kyaraben apply`

Reads the config, installs emulators, generates emulator configs, and creates the folder structure. If the changes conflict with your existing configuration, `kyaraben apply` asks for confirmation before it overwrites files.

```
$ kyaraben apply

Applying kyaraben configuration...

Using ~/Emulation (existing data preserved)
Installing emulators (this may take a while on first run)...
Adding to application menu...
Configuring emulators...
  Installed to: ~/.local/state/kyaraben/packages/...

  Applied: ~/.config/retroarch/retroarch.cfg
  Applied: ~/.config/duckstation/settings.ini
  Applied: ~/.config/mgba/config.ini
  Applied: ~/.config/PCSX2/inis/PCSX2.ini

Done!

Your collection is ready at: ~/Emulation
Place your ROMs in the appropriate subdirectories.
```

Use `--dry-run` to preview config changes without applying them.

### `kyaraben init`

Creates a default `config.toml` with popular systems enabled:

```
$ kyaraben init

Created configuration at ~/.config/kyaraben/config.toml

Enabled 13 systems with default emulators.
Run 'kyaraben apply' to install emulators and create directories.
```

Options:

- `-d, --collection <PATH>`: set the collection path (default: `~/Emulation`)
- `-f, --force`: overwrite existing configuration
- `--headless`: create a headless configuration for sync hubs (no emulators)

With `--headless`, `kyaraben apply` creates directories for all systems but does not install emulators. See [headless server guide](/guides/headless-server/) for setup instructions.

### `kyaraben update`

Checks for CLI updates and installs them. The desktop app has its own update mechanism.

```
$ kyaraben update

Checking for updates...

New version available: v0.9.1
Downloading...
Updated to v0.9.1
```

If already up to date:

```
$ kyaraben update

Checking for updates...
Already up to date.
```

### `kyaraben sync`

Manage save synchronization. See [app reference](/using-the-app/#synchronization) for an overview.

#### Enabling synchronization

Edit `~/.config/kyaraben/config.toml`:

```toml
[sync]
enabled = true
```

Then run `kyaraben apply` to install Syncthing.

#### `kyaraben sync pair [CODE]`

Pairs two devices. Without a code, this device generates a pairing code. With a code, this device joins the device that generated it. If the synchronization service is not running, the command installs and starts it.

```
$ kyaraben sync pair
Installing synchronization service...
Pairing code: K7X9M2
Waiting for devices... (expires in 5 minutes)

Paired with steamdeck-kyaraben
```

On the second device:

```
$ kyaraben sync pair K7X9M2
Connecting...
Paired with desktop-kyaraben
```

#### `kyaraben sync pair --device-id`

Shows the full 56-character device ID instead of a pairing code. Use this if the relay server is unavailable:

```
$ kyaraben sync pair --device-id
Device ID: LGFPDIT7-SKNNJVJZ-A4FC7QNC-...

# On the other device, join using the full device ID
$ kyaraben sync pair LGFPDIT7-SKNNJVJZ-A4FC7QNC-...
```

This works across networks through the Syncthing relay servers.

#### `kyaraben sync status`

Shows the synchronization state, the connected devices, and the progress and conflict count of each folder.

```
$ kyaraben sync status

Sync: enabled
Status: synced
Device ID: LGFPDIT7-SKNNJVJZ-A4FC7QNC-...
UI: http://127.0.0.1:8484

Paired devices:
  steamdeck-kyaraben                 connected

Synced folders:
  ROMs                 idle
  Saves                idle
    2 conflict file(s)
  States               idle
  Screenshots          idle
```

If there are conflicts, the status is `conflict`, and each affected folder shows its conflict count. See [resolving conflicts](/collection/#resolving-conflicts).

#### `kyaraben sync add-device <DEVICE-ID>`

Adds a device by its 56-character Syncthing device ID. Use this to pair manually, without the interactive flow.

#### `kyaraben sync remove-device <ID-or-NAME>`

Removes a paired device by its device ID or name.

### Sync configuration

Syncthing runs as a systemd user service. Its configuration is separate from other Syncthing installations.

| Setting          | Default                              |
| ---------------- | ------------------------------------ |
| Config directory | `~/.local/state/kyaraben/syncthing/` |
| Listen port      | 22100                                |
| Discovery port   | 21127                                |
| GUI port         | 8484                                 |
| Relay servers    | Enabled                              |
| Device name      | `<hostname>-kyaraben`                |

Override ports in `~/.config/kyaraben/config.toml`:

```toml
[sync.syncthing]
listen_port = 22100
discovery_port = 21127
gui_port = 8484
relay_enabled = true
global_discovery_enabled = false
```

### Ignore patterns

Kyaraben ignores regenerable data by default:

```
**/shader_cache/**
**/cache/**
**/*.tmp
.DS_Store
Thumbs.db
```

Add custom patterns in `~/.config/kyaraben/config.toml`:

```toml
[sync.ignore]
patterns = [
  "**/shader_cache/**",
  "**/logs/**",
]
```

Patterns use Syncthing's ignore syntax. Prefix with `!` to un-ignore.

Ignore patterns apply only to the device that has them:

- On the primary, ignored files do not go to any secondary.
- On a secondary, that device does not receive the ignored files. Other devices still synchronize them.

Use this to keep large files off a device with little storage, such as a Steam Deck.

#### Example: exclude large ROM formats

To synchronize only small ROMs and skip disc-based games:

```toml
[sync.ignore]
patterns = [
  # Skip disc images (PS1, PS2, GameCube, Wii, etc.)
  "roms/**/*.iso",
  "roms/**/*.chd",
  "roms/**/*.cso",
  "roms/**/*.rvz",
  "roms/**/*.wbfs",
  # Skip optical formats
  "roms/**/*.bin",
  "roms/**/*.cue",
]
```

#### Example: skip EmulationStation DE videos

Scraped videos can be several gigabytes per system. To synchronize box art and screenshots without videos:

```toml
[sync.ignore]
patterns = [
  "frontends/esde/media/**/videos/**",
]
```

To synchronize only gamelists (metadata) and no media:

```toml
[sync.ignore]
patterns = [
  "frontends/esde/media/**",
]
```

### Sync troubleshooting

#### Pairing code rejected

Codes expire after 5 minutes. Cancel pairing on the primary and start again.

#### Devices paired but not synchronizing

1. Make sure that `kyaraben sync status` shows "connected".
2. If a firewall blocks connections, see the [Syncthing firewall documentation](https://docs.syncthing.net/users/firewall.html).

### `kyaraben import scan`

Analyzes an existing ROM collection and shows what you can import into the Kyaraben structure. Use it to migrate from another setup, such as EmuDeck, or to merge files from many locations. The command only reads. It does not move or modify files.

```
$ kyaraben import scan ~/Games/Emulation

Back up your collection before copying anything.

Existing collection: /home/user/Games/Emulation
Kyaraben collection: /home/user/Emulation

Overall: +0 in Kyaraben, +2.3 GB to import

===========================================================================
PlayStation
===========================================================================

ROMs                                               +0  +1.8 GB

  Found at:        /home/user/Games/Emulation/roms/psx
                   47 files, 1.8 GB
  Kyaraben expects: /home/user/Emulation/roms/psx
                   (not found)

  Missing from Kyaraben (47 files, 1.8 GB):
    Final Fantasy VII (USA).chd
    Metal Gear Solid (USA) (Disc 1).chd
    ... and 45 more
```

Options:

- `--esde <PATH>`: specify the ES-DE data directory. Defaults to `~/ES-DE` if it exists.
- `--format <text|json>`: output format. Defaults to `text`.

Use the JSON format in scripts:

```
$ kyaraben import scan ~/Games --format json | jq '.summary.totalOnlyInSource'
2463187456
```
