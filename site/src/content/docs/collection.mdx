Your <Collection /> (default `~/Emulation`) keeps all your emulation data. This page describes its structure and its synchronization.

## Folder structure

```
~/Emulation/
├── roms/                 # ROM files, organized by system
│   ├── snes/
│   ├── psx/
│   ├── switch/
│   │   └── updates/      # Switch updates and DLC, loaded by Eden
│   └── ...
├── bios/                 # BIOS and firmware files, organized by system
│   ├── psx/
│   └── ...
├── saves/                # Save files (memory cards, battery saves), by system
│   ├── psx/
│   ├── gba/
│   └── ...
├── states/               # Emulator save states, by emulator
│   ├── duckstation/
│   ├── dolphin/
│   └── ...
├── screenshots/          # Captured screenshots, by emulator
│   ├── retroarch/
│   ├── duckstation/
│   └── ...
└── frontends/            # Frontend metadata and media
    └── esde/
        ├── gamelists/    # Game lists per system
        └── media/        # Scraped artwork per system
```

Saves are in system folders, so that all emulators for a system can share them. States and screenshots are in emulator folders, because their formats are specific to each emulator. Kyaraben never reads, modifies, or deletes your ROMs, saves, or BIOS files.

### Symlink strategy

Kyaraben uses symlinks to send emulator data to your <Collection />. For example, Dolphin stores GameCube saves in `~/.local/share/dolphin-emu/GC/`. Kyaraben replaces that directory with a symlink to `~/Emulation/saves/gamecube/`. The emulator keeps its default settings, and the data goes to the collection.

### Switch updates and DLC

Put Switch update and DLC files (`.nsp` or `.xci`) in `roms/switch/updates/`, in any subfolder layout. Eden loads them from there and does not install them into its NAND. They sync with the rest of your ROMs. The folder contains a `noload.txt`, so EmulationStation DE does not list these files as games.

## What syncs

When synchronization is on, these folders synchronize between devices:

| Content                     | Sync behavior |
| --------------------------- | ------------- |
| `roms/`                     | Bidirectional |
| `bios/`                     | Bidirectional |
| `saves/`                    | Bidirectional |
| `states/`                   | Bidirectional |
| `screenshots/`              | Bidirectional |
| `frontends/esde/gamelists/` | Bidirectional |
| `frontends/esde/media/`     | Bidirectional |

A deletion on one device goes to all devices. The exception is ROM folders when ROM deletion protection is on, which is the default. See [protecting ROMs from deletion](#protecting-roms-from-deletion).

### EmulationStation DE gamelists and media

Scraped EmulationStation DE metadata (descriptions, ratings) and media (screenshots, videos, box art) synchronize between devices. Each device keeps its own play history. To prevent conflicts, Kyaraben removes play statistics (playcount, playtime, last played) before sync, and adds the local statistics back on import.

Scraped videos can be large. To exclude them from synchronization, see [ignore patterns](/using-the-cli/#ignore-patterns).

## File versioning

Syncthing keeps old versions of save and state files for 30 days. ROM and BIOS
folders do not use versioning.

## Protecting ROMs from deletion

When the "ignore ROM deletions" sync setting is on, a device keeps its ROMs when another device deletes them. The setting is on by default. ROMs have no file versioning because they are large and you can replace them, so this setting protects them instead.

The setting applies only to the device that has it. Devices do not share it. A device keeps all its ROMs only if its own setting is on. When you delete a ROM, the deletion removes it from all peers that have the setting off. You can thus delete ROMs on one device to free space, and keep them on the protected devices.

To change the setting:

- On desktop and Steam Deck, use the sync settings.
- On a headless server, run `kyaraben sync ignore-rom-deletions on` or `off`. `kyaraben sync status` shows the setting for this device and its peers.

If you use a [headless server](/guides/headless-server/) as a sync hub, turn the setting on for the server and off on your other devices. The server then keeps a complete archive of all ROMs. Deletions still go between your other devices, so you can free space on them. To get back a deleted ROM, copy it from the server.

While the setting is on:

- Kyaraben does not apply ROM deletions from other devices. To remove a ROM from all devices, delete it on each device.
- A rename or move is a delete and a create. When you rename a ROM on another device, the copy with the old name can stay as a duplicate.

Handheld integrations such as [NextUI](/nextui/) have the same setting, but it is off by default. On a handheld, deletions usually free card space.

## Resolving conflicts

If two devices modify the same file before they sync, Syncthing keeps both versions and writes one of them to a conflict file, with a name such as `game.sync-conflict-ABCD123-20260307-120000.srm`.

To see the number of conflicts in each folder, look at the sync status in the UI, or run `kyaraben sync status`.

To resolve a conflict:

1. Find the file with `.sync-conflict-` in its name in the affected folder.
2. Compare it with the original file and choose the version to keep.
3. Delete the other version.

Conflict files sync between devices, so resolve each conflict on one device only.
